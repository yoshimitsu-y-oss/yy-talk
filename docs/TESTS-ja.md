## 導入前に評価するリスク

- 1つの映像ROOMと複数の音声ROOMを開くため、接続数・上り帯域・LiveKit料金が増える。会社の同時接続人数で負荷試験する。
- 4W/PGMを送信前に分離するため、v56の物理ステレオtrack直接送信からWeb Audioを経由する経路へ変わった。過去の音切れ対策と競合する可能性がある。機材での長時間試験が必須。
- ACL変更時はROOM削除に伴う短い音声・映像中断がある。画面共有は再選択を要する場合がある。VIDEO権限を外すと現状ROOM接続を完了できない。
- 管理者による強制TALK/LISTENは信頼したUIに反映する。悪意あるクライアントのマイク操作を物理的に強制する保証はない。パーティー参加権限はSFU ROOMで分離する。
- 背景動作中にiOSがHTTP更新を止めると、セキュリティ上leaseが失効して切断される。ロック画面での運用を実機で評価する。
- Directory API、Access JWKS、LiveKit制御APIの障害時はアクセス拒否・切断となる。Google APIクォータを会社の規模で確認する。
- CDNのライブラリはバージョンを固定するが、SRIや自己ホスト化は未実施。CSPは既存インライン実装のためunsafe-inlineを残す。コード内の秘密情報は除去し、ライブトークンだけを必要範囲で利用する。
- Google/Cloudflare/LiveKit設定と旧公開経路の保護はコードだけでは完了しない。現段階のPRを本番承認済みとは扱わない。
